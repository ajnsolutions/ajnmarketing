## Objective

Build the **evidence, confidence, and persistence foundation** for competitor observations — a new, additive module that:

1. Reads an owner's tracked Market Radar entries (`lib/market-radar/persistence.ts`'s `listMarketRadarEntriesForUser`, kind `competitor` only — benchmarks are for inspiration, not competitive observation, per `MARKET_RADAR.md`).
2. Cross-references each tracked competitor against the **existing, already-built** `lib/market-context/providers/competitorProvider.ts` signal (profile-declared competitor information already present in this repository — not a new external data source).
3. Decides, using an explicit, pure, testable scoring function, whether a given piece of signal is a "meaningful observation" worth persisting (this is the actual judgment-and-filtering logic this task delivers — not every signal item is meaningful; a bar exists and is enforced in code, not left to chance).
4. Persists qualifying observations with a source-attributed evidence record and a `low`/`medium`/`high` confidence level (following `GraphEvidence`'s shape/spirit), scoped per tenant exactly like every other persisted record in this repo (ADR-0001).

This is **persistence, evidence-model, and scoring logic only — no UI, no new route, no new external data source, and no live monitoring/scraping of real competitor websites, pricing, or activity.** Tasks 004 and 005 (already queued, both depending on this one) are the UI/surfacing layers that read what you build here.

## Scope — exactly these changes

1. **A new Supabase migration file**, `supabase/migrations/038_competitor_observations.sql` (check the actual highest-numbered file in `supabase/migrations/` first in case a later migration has been added since this prompt was written, and number accordingly). Follow the exact structural convention of `037_market_radar.sql`: a `public.competitor_observations` table with (at minimum) `id uuid primary key default gen_random_uuid()`, `user_id uuid not null references auth.users(id) on delete cascade`, `business_profile_id uuid not null references public.business_profiles(id) on delete cascade`, `market_radar_entry_id uuid not null references public.market_radar_entries(id) on delete cascade` (the tracked competitor this observation is about), `summary text not null` (the plain-language observation), `confidence text not null check (confidence in ('low', 'medium', 'high'))`, `source_label text not null` (human-readable provenance, e.g. what produced this observation), `occurred_at timestamptz` (nullable — not every signal has a specific event time), `created_at`/`updated_at timestamptz` with the same trigger pattern as existing migrations. Index `business_profile_id`, `user_id`, and `market_radar_entry_id`. Enable RLS with select/insert/update/delete policies scoped to `auth.uid() = user_id`, mirroring `037_market_radar.sql`. **Do not** apply/run this migration against any database — writing the file is the entire deliverable (`AGENTS.md` rule 13).
2. **`lib/competitor-observations/types.ts`** — a `CompetitorObservationConfidence` type (`"low" | "medium" | "high"`, matching `ConfidenceLevels` in spirit) and a `CompetitorObservation` type mirroring the table's columns (camelCase, following `lib/opportunity-engine/persistence.ts`'s `mapRow` pattern).
3. **`lib/competitor-observations/scoring.ts`** — the pure, exported, unit-testable "is this meaningful" logic: a function (e.g. `scoreCompetitorSignal(signal, trackedEntry): { meaningful: boolean; confidence: CompetitorObservationConfidence; summary: string } | null`) that takes one `MarketContextItemInput`-shaped competitor signal (from `competitorProvider.ts`) and the `MarketRadarEntry` it's about, and decides whether it clears the bar to become a persisted observation, and at what confidence. Base the confidence mapping on the signal's own `confidenceScore` (0-100, already present on `MarketContextItemInput` — read `lib/market-context/types.ts` for its exact shape) rather than inventing a new scoring dimension from nothing. Be honest and conservative: a fallback/mock signal (`metadata.isFallback: true` in `competitorProvider.ts`) must never be scored as meaningful — it is explicitly synthetic placeholder copy, not a real observation about a real tracked competitor, and persisting it would violate `MARKET_RADAR.md`'s "no fabricated competitive claims" rule.
4. **`lib/competitor-observations/persistence.ts`** — tenant-scoped functions following the `*ForUser(supabase, userId, ...)` convention:
   - `listCompetitorObservationsForUser(supabase, userId, businessProfileId)` — returns all observations for that business, most recent first.
   - `recordCompetitorObservationForUser(supabase, userId, businessProfileId, observation: { marketRadarEntryId, summary, confidence, sourceLabel, occurredAt? })` — inserts and returns the new row, or `null` on failure (matching this repo's existing null-on-failure convention).
   - `generateCompetitorObservationsForUser(supabase, userId, businessProfileId)` — the orchestration function: lists tracked competitors (Task 001), pulls current competitor signal (`competitorProvider.ts`), runs each through `scoreCompetitorSignal`, and persists the ones that qualify. Must not create duplicate observations for signal it has already recorded (decide and document a clear de-duplication rule — e.g. by `market_radar_entry_id` + `summary`, or a time window — rather than leaving this ambiguous).
5. **Unit tests** (`unit-tests/competitor-observation-engine.test.ts`, `node:test`/`node:assert` style matching every other file in `unit-tests/`): thorough coverage of `scoreCompetitorSignal` — a fallback/mock signal is never meaningful; a low-confidence-score signal maps to `low` (or is filtered out entirely, per whatever bar you define — document the exact thresholds in code comments since they are a real, load-bearing decision); a high-confidence-score signal about a genuinely tracked competitor maps to `high`; a signal about a business the owner has never tracked in Market Radar is never scored (it's not scoped to anything the owner asked to watch). Do not unit-test the raw Supabase persistence functions directly (this repo's established convention — see Task 001's own prompt and `lib/opportunity-engine/persistence.ts`'s test coverage for why).
